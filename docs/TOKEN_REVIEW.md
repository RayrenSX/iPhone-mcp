# Token 开销审查

审查日期：2026-10-15。基线提交：`caef854`；本机 MCP SDK：`1.30.0`。

已检查全部 28 个 MCP 工具，以及截图/OCR、HTTP 适配、后台启动、驱动安装、诊断脚本和原生补丁中的相关流程。下方“发现”记录修改前基线；“修复结果”记录后续已落实的代码变更。未修改客户端权限配置或向手机发送输入。

## 修复结果（2026-10-15）

已落实：

- `snapshot` 及新增图片返回模式的 `wait_for` 关闭自动结构化输出，图片仅通过 `content` 返回一次。
- 快照默认紧凑 OCR 和 720px 最大宽度，支持 `compact=false` 的完整字段与 `max_width=0` 的原图细节；`include_image=false` 不编码或传输图片。
- 裁剪区域过滤文字框和完整视图中的全文，保留原生坐标与原始 ID。服务端保留原始精度，并拒绝点击该快照未返回的文字框 ID。
- 保留快照中的完整新鲜状态，统一流程以复用状态；doctor 删除独立状态调用，第二次 OCR 检查不重发图片。截图前后几何检查继续保留。
- `wait_for(return_snapshot=true)` 返回匹配帧及快照元数据，文字条件复用 OCR；状态条件截图后重新检查条件，超时不返回新快照。

- 保留全部 28 个工具，清理工具输入 schema 中的显示标题；字段名、约束、必填项、枚举和权限注解不变。压缩全局说明，保留坐标、租约、派发、粘贴提示和安装失败约束。
- 更新诊断/探测脚本和 README/SETUP，修正工具数量与客户端迁移说明。工具配置分组和剪贴板范围读取没有纳入本次实现。

## 测量口径

- 工具目录来自本机实际执行 `mcp.list_tools()`，按 `model_dump(mode="json", exclude_none=True)` 后的紧凑 JSON 统计字符数。
- 协议问题通过测试中的隔离 HTTP 服务和真实 stdio MCP 连接复现；没有读取真实设备内容。
- OCR 数据和分辨率比较使用合成样本，不能代表所有页面。
- 下文的字符数、Base64 长度和像素数均不是模型 token 数。客户端可能过滤结构化结果、按需加载工具或缓存提示词，图片计费也取决于模型和客户端处理方式。本次未测量客户端最终提交给模型的载荷或账单。

## 优先处理的发现

### 1. P1：snapshot 把图片 Base64 和文字复制进 structuredContent

位置：`src/iphonemirror_mcp/server.py:278`。

`snapshot` 标注返回 `list[TextContent | ImageContent]`。当前 FastMCP 自动从该类型生成输出 schema，并同时返回：

```text
content: [文字元数据, 原生 MCP 图片块]
structuredContent.result: [同一份文字元数据, 含同一 Base64 的图片对象]
```

已通过 stdio 调用 `snapshot(use_ocr=false)` 确认两处图片数据相同。其他普通 `dict` 返回工具在本机没有自动生成结构化输出，不能将此结论推广到所有工具。

影响：图片编码和元数据重复传输；客户端若将 `structuredContent` 作为 JSON 文本提供给模型，重复的 Base64 会带来额外文本 token。即使客户端过滤它，也仍有协议传输与序列化开销。

建议：给 `snapshot` 显式设置 `structured_output=False`，继续保留 `content` 中的文字和图片块。若需要保留结构化接口，则显式构造结果，让结构化部分只承载必要元数据，不放图片 Base64，并明确兼容策略。

已在内存中使用 `Tool.from_function(snapshot, structured_output=False)` 验证候选方案：120×240 合成图片对应的序列化结果由 **3,064 字符降为 1,498 字符，减少 51.1%**，`content` 完全一致；工具目录还能少 **1,580 字符**的图片/文字输出 schema。真实图片更大时，绝对减少量会增加，但不能据此宣称模型 token 固定减半。

兼容注意：依赖旧 `structuredContent.result` 的客户端需要迁移；现有仓库诊断和 probe 从 `content` 解析数据。应补充实际 stdio 回归测试，断言图片只在 `content` 出现、没有 Base64 的结构化副本。当前 stdio 测试未覆盖 `snapshot` 返回形态，因此现有测试全部通过也未发现此问题。

### 2. P2：OCR 同时返回全文和逐行文本，且包含可推导字段

位置：`src/iphonemirror_mcp/vision.py:75`、`src/iphonemirror_mcp/server.py:302`。

`ocr.text` 与 `ocr.elements[*].text` 内容重叠。每一行还重复 `source="ocr"`，同时返回 `bounds` 和可从它计算的 `center`；坐标可能包含较长小数。每次快照还重复 `note`、坐标变换 `formula` 等固定说明。

建议增加紧凑视图，内部仍保留完整观察记录：

- 对外默认返回 `id/text/bounds`，全文作为可选项；不要未经兼容处理直接删除 `ocr.text`，probe 会读取它。
- 外部坐标可保留 1 位小数；点击复核和派发继续使用内部原始精度。
- 将固定来源、OCR 能力限制和坐标公式放到简短接口说明中，避免每行/每次重复。保留客户端实际需要的坐标变换数值。
- 采用 `json.dumps(..., ensure_ascii=False, separators=(",", ":"))`；不应转义中文来追求表面上的 ASCII 输出。

40 行合成中英文 OCR 样本：当前数据的紧凑 JSON 为 **7,983 字符**；保留语言和 `id/text/bounds`、坐标保留 1 位小数后为 **3,497 字符，减少 56.2%**。这是 OCR 部分的样本字符收益，未包括图片和设备状态，也不是实测 token 节省比例。

### 3. P2：裁剪只裁图片，OCR 仍返回整个屏幕

位置：`src/iphonemirror_mcp/server.py:291`、`src/iphonemirror_mcp/vision.py:90`。

`region` 已能减少显示图片范围，但 OCR 仍识别并返回全屏所有文字框。只查看一个输入框或弹窗时，屏幕其余文字继续进入上下文。

建议：优先保留当前完整识别和内部记录，只过滤对外返回的、与区域相交的文字框，并同步限制返回全文的范围。保留原始 element ID 和原生坐标，不能过滤后重新编号。过滤后如果某一行只有部分区域可见，应明确其文字框仍来自完整识别。

后续如需真正只识别 ROI，再处理 OCR 坐标偏移、跨边界文字和点击前重新识别的一致性。仅过滤输出更容易兼容现有点击校验。

### 4. P2：默认图片几乎保持原图大小，缺少文字观察输出模式

位置：`src/iphonemirror_mcp/server.py:157`、`:279`。

`screenshot` 固定返回原始 PNG；`snapshot` 默认宽度 1080，并且始终返回图片。以仓库报告中的 1082×2340 尺寸做合成验证：

| max_width | 输出尺寸 | 像素数 | 相对默认像素减少 |
|---|---|---:|---:|
| 1080，当前默认 | 1080×2336 | 2,522,880 | — |
| 720 | 720×1557 | 1,121,040 | 55.6% |
| 540 | 540×1168 | 630,720 | 75.0% |

现阶段无需改代码即可对普通页面使用 `snapshot(max_width=720)`，小字或细节不清时提高分辨率，已知目标区域时使用 `region`。图片 token 是否下降及下降幅度须在目标客户端验证，不能直接用像素比例推断。

建议给现有 `snapshot` 增加可选输出模式，例如图片、文字或两者，以支持只读文字提取任务。保持一次输入前后的画面观察要求；不能将 OCR 存在当作按钮可点或操作已成功的证明。也不建议直接把全局默认改成低分辨率，细节丢失可能造成更多重试。

减少 PNG 字节、改 JPEG 或调编码质量主要影响传输和延迟；图片尺寸及客户端处理方式未变时，不能直接宣称减少视觉 token。

### 5. P2：工具目录可以精简，但应使用可选配置

位置：`src/iphonemirror_mcp/server.py:46` 及工具注册。

实际 28 个工具的紧凑目录为 **19,732 字符**；初始化 instructions 本文为 **2,680 字符**。以下为对实际目录做内存变换的测量：

| 目录方案 | 字符数 | 相对当前减少 |
|---|---:|---:|
| 当前完整目录 | 19,732 | — |
| 关闭 snapshot 自动输出 schema | 18,152 | 8.0% |
| 再删除冗余 JSON Schema title | 15,689 | 20.5% |
| 上述基础上的 14 工具日常配置示例 | 8,773 | 55.5% |

14 工具示例：`start_iphonemirror`、`list_devices`、`get_device_status`、`snapshot`、`acquire_control`、`release_control`、`tap`、`swipe`、`scroll`、`click_element`、`type_text`、`press_key`、`press_shortcut`、`wait_for`。

建议：

- 保留完整工具配置作为兼容入口，按需增加日常/安装/高级触控等启动配置；配置切换需要重新连接，不能在运行中静默移除工具。
- 日常配置不加载安装工具时，应说明缺少运行时如何切换配置，不能让 `start_iphonemirror` 指向未暴露的 `get_setup_status`。
- 清理自动生成的无信息 `title`，保留类型、必填项、范围、枚举和权限注解；具体 SDK 注册方式需测试验证。
- 压缩重复说明，但工具自身仍保留必要的租约、原生坐标、过期快照及不确定输入不可重试等约束，避免客户端忽略全局 instructions 后失去关键信息。

这些数字是目录体积，不代表每轮都会按同样数量消耗模型 token；按需发现和提示词缓存会改变收益。不建议为减少工具数而设计一个巨大通用 `action` 参数接口，它可能增加选参错误和补救调用。

### 6. P2：状态返回和启动后的调用有重复

位置：`src/iphonemirror_mcp/server.py:144`、`:150`、`:302`，`src/iphonemirror_mcp/runtime.py:171`。

`list_devices` 返回连接、能力和几何信息，`get_device_status` 返回完整状态，`snapshot` 又嵌入完整 `frame.status`。README 推荐的启动流程和 server instructions 观察入口也不完全一致，容易造成模型机械地先查状态、再单独截图、再取快照。

建议统一常规入口为：启动/选择设备后取 `snapshot`，直接使用其中最新状态和几何；只有诊断、能力检查或明确需要更新状态时再单独调用。配置安装验收按 AGENTS.md 保留专门的状态和截图验证要求。

接口可增加可选简版状态：保留在线、投屏、控制可用性、几何版本及尺寸，并在失败时返回原因；完整能力清单和诊断信息通过完整视图获取。不能为了省字删除多设备 ID、权限边界、不可用原因或 `actionRequired`。完整状态来自原生 API，本次没有用真实设备载荷量化这部分收益。

### 7. P2：wait_for 与安装进度仍可减少模型参与轮次

位置：`src/iphonemirror_mcp/server.py:405`、`:441`，`src/iphonemirror_mcp/setup.py:193`。

`wait_for` 已经在服务端轮询并只返回匹配结果，这是现有的有效优化；应优先于让模型不断执行 `snapshot → 判断 → wait`。但匹配后通常又需要单独获取快照，增加一次模型工具往返。

建议给 `wait_for` 增加可选的匹配时快照返回，复用最后一帧并按正常快照规则生成 ID、状态和坐标变换。只有需要观察结果时才附图；状态等待不能假装已经拥有一帧图片。

安装 `get_setup_status` 每次立即返回完整状态，没有等待新进展的参数。建议提供有上限的等待、revision/after_revision 和推荐轮询间隔；阶段、终态及需要人处理的动作必须及时返回。保留现有立即查询能力。安装进度没有无限日志数组，当前不存在“每次重发全部原生日志”的问题。

不要添加自动重试输入或不确定驱动事务来减少轮次；这会破坏当前的明确语义。

### 8. P3：长剪贴板文本应能按需读取

位置：`src/iphonemirror_mcp/server.py:262`。

`read_clipboard` 原样返回 API 文本；长内容可能一次占用大量上下文。建议可选 `offset/max_chars`，同时返回总长度、实际范围及是否截断，默认值和旧行为应有兼容策略。对需要精确文本的任务不能静默截断，也不能将截断片段误报为完整内容。写入和粘贴工具不应重复回显用户刚提供的整段文本。

## 全部工具覆盖

| 工具 | 审查结论与优化方向 |
|---|---|
| `start_iphonemirror`、`get_app_status`、`open_independent_window` | 返回较小；统一启动后观察路径即可。窗口仅按用户要求打开。重复启动的内部 API/进程处理主要属于延迟问题。 |
| `prepare_iphone_environment`、`get_setup_status` | 适合移入可选安装工具配置；增加有界进度等待，保留全部人工动作和失败结果。 |
| `list_devices`、`get_device_status` | 可提供简版/完整视图；复用快照中已有的最新状态，避免重复查询。 |
| `screenshot`、`snapshot` | 优先去掉结构化图片副本；精简 OCR、过滤区域文字、按需控制图片尺寸与输出内容。 |
| `acquire_control`、`release_control` | 返回已精简，密钥保留在服务端；保留独立租约操作和 finally 释放。按任务时长选合理 TTL，不能以省调用为由默认延长到最大。 |
| `tap`、`long_press`、`swipe`、`touch_path`、`touch_down`、`touch_up` | 返回通常很小，主要是工具 schema 成本。高级触控可选加载；触摸轨迹表达连续手势，不应为省参数任意降采样。 |
| `click_element` | 已只传快照和文字框 ID，避免再次发送长坐标；其内部重新截图/OCR 属于本地校验，不额外产生模型轮次，应保留。 |
| `scroll`、`drag` | 便捷接口能减少模型计算或较长路径参数。与底层工具有重叠，可通过可选配置控制，而非直接删除。 |
| `type_at` | 已将点击和粘贴合并；保留部分派发错误，不能自动重试。可评估可选的操作后观察，但须保留粘贴权限提示处理。 |
| `press_key`、`press_shortcut` | 短参数与短响应；保留快捷动作枚举和设备能力检查。内部 status 请求只影响 API 延迟，不等于多一次模型调用。 |
| `type_text`、`write_clipboard` | 用户提供的文本是主要必要输入；避免回显。不应为节省 token 改变粘贴内容或跳过 iOS 许可提示。 |
| `read_clipboard` | 可选范围读取，清楚标明截断。 |
| `wait`、`wait_for` | 优先使用服务端条件等待；匹配时可选返回观察，避免模型自行轮询。 |

## 应保留的现有设计

- `capture` 在截图前后检查几何，防止旋转/尺寸变化；这三个本地 HTTP 请求不是三个模型工具调用。删除它们主要节省延迟，不能直接计算为 token 收益。
- `click_element` 的新截图、OCR 位置复核和 30 秒快照有效期保证文字框引用的基本可靠性。
- 输入需要显式租约，返回 `dispatched` 仅表示派发，仍需新画面确认效果。
- 连接错误和超时不会自动重试输入；`type_at` 会明确报告点击已派发而粘贴未确认。
- 驱动安装返回经过整理的状态与动作，不向模型返回原生日志、密钥或完整设备序列号。
- OCR 引擎复用、避免 PNG 重编码、减少 CPU 工作可以另行优化，但本身不减少模型 token。

## 建议落地顺序与验收
